# URL → Markdown LLM 핸드오프

## 개요

웹 페이지 URL을 붙여넣으면 본문을 Markdown으로 추출해 보여주고, 복사·다운로드하거나
프롬프트를 붙여 ChatGPT/Claude로 바로 넘길 수 있는 1회성 변환 도구.

## 사용자 흐름과 범위

### 1. 입력

- URL 입력 필드에 값을 붙여넣거나 직접 입력할 수 있다.
- "지우기" 버튼을 누르면 입력 필드와 결과 화면(제목/저자/Markdown)이 모두 초기 상태로
  리셋된다.
- 유효한 URL 형식이 아니면 변환을 시도하지 않고 입력 필드 옆/아래에 인라인 에러를
  표시한다.

### 2. 변환

- 유효한 URL을 제출하면 서버가 대상 페이지를 가져와 defuddle로 본문을 정제하고
  Markdown으로 변환한다.
- 변환 중에는 로딩 상태를 표시한다.
- 페이지를 가져오지 못하거나(네트워크 오류, 404, 로그인 필요, 접근 차단 등) 본문
  추출에 실패하면 실패했다는 에러 메시지를 표시하고, 같은 URL로 다시 시도할 수 있다.

### 3. 결과 확인

- 성공하면 페이지 제목과 저자를 헤더에 함께 표시한다.
- 추출된 Markdown을 렌더링된 형태로 보여준다.

### 4. 내보내기

- **복사하기**: 추출된 Markdown 본문만 클립보드에 복사한다(프롬프트는 포함하지 않는다).
- **.md 다운로드**: 추출된 Markdown 본문만 `.md` 파일로 다운로드한다(프롬프트는
  포함하지 않는다). 파일명은 페이지 제목 기반으로 만들고, 제목이 없으면 고정된 기본
  파일명을 쓴다.
- **ChatGPT로 열기 / Claude로 열기**: 현재 선택된 프롬프트(프리셋 또는 직접 입력)가
  있으면 "프롬프트 + Markdown 본문"을, 없으면 "Markdown 본문"만 클립보드에 복사하고
  해당 서비스의 새 대화 페이지를 새 탭으로 연다. 두 서비스 모두 자동으로 프롬프트를
  채워주지 않으며, 사용자가 새 탭에서 직접 붙여넣는다(근거: [llm-handoff-export
  결정](../../decisions/llm-handoff-export.md)).

### 5. 프롬프트

- 프리셋 3종: "요약해줘", "한국어로 번역해줘", "쉽게 설명해줘".
- 프리셋 옆 "직접 입력"을 선택하면 텍스트 입력창이 나타난다. 여기 입력한 프롬프트는
  저장되지 않으며 페이지를 벗어나거나 새로고침하면 사라진다.
- 결과 화면에서 프롬프트 선택을 언제든 바꿀 수 있고, 바꿔도 변환을 다시 하지 않는다.

### 6. 다크모드

- 화면에서 라이트/다크 모드를 토글할 수 있다.
- 선택한 모드는 브라우저에 저장되어 다음 방문에도 유지된다.

## 수용 기준

- [ ] 유효하지 않은 URL 형식을 제출하면 변환이 시작되지 않고 인라인 에러가 보인다.
- [ ] 유효한 URL을 제출하면 로딩 상태 → 성공 시 제목과 저자, 렌더링된 Markdown이
      보인다.
- [ ] 대상 페이지를 가져오거나 파싱할 수 없으면 에러 메시지가 보이고 같은 URL로
      재시도할 수 있다.
- [ ] "지우기"를 누르면 입력값과 결과 화면이 모두 초기 상태로 돌아간다.
- [ ] "복사하기"로 클립보드에 담기는 내용에는 프롬프트가 섞이지 않는다.
- [ ] ".md 다운로드"로 받은 파일 내용에는 프롬프트가 섞이지 않는다.
- [ ] 프롬프트를 선택한 상태에서 "ChatGPT로 열기"/"Claude로 열기"를 누르면 프롬프트와
      Markdown 본문이 함께 클립보드에 복사되고, 각 서비스의 새 대화 페이지가 새 탭으로
      열린다.
- [ ] 프롬프트를 선택하지 않은 상태에서 같은 버튼을 누르면 Markdown 본문만 복사되고
      새 탭이 열린다.
- [ ] "직접 입력" 프롬프트는 새로고침 후 남아있지 않다.
- [ ] 다크모드 토글 상태는 새로고침 후에도 유지된다.

## 결정된 제약과 근거

- **LLM 핸드오프는 복사+새 탭 방식으로 통일한다.** ChatGPT의 URL 프리필은 비공식이고
  글자 수 제한이 있으며, Claude는 웹에 프리필 방법이 없고 데스크톱 앱 전용 딥링크만
  존재해 대다수 웹 사용자에게 동작하지 않는다. 자세한 근거는
  [llm-handoff-export](../../decisions/llm-handoff-export.md) 참고.
- **대상 페이지는 서버에서 가져온다.** 브라우저가 임의의 타 사이트를 직접 fetch하면
  대부분 CORS로 막히므로, URL 가져오기는 서버 쪽 책임이다.

## 가정 (뒤집을 수 있는 기본값)

- 로그인/계정/변환 이력 저장은 없다 — 1회성 변환 도구로 요청되었고 별도 언급이 없었다.
- 실패 사유(네트워크 오류/404/로그인 필요/차단 등)를 세분화해서 안내하지 않고, 공통
  에러 메시지 + 재시도로 처리한다.
- 다운로드 파일명은 제목을 슬러그화해 사용하고, 제목이 없으면 고정 기본 파일명을
  쓴다.
- 다크모드는 시스템 설정을 따르지 않고 수동 토글이며, 브라우저 로컬 저장(서버 저장
  없음)만 한다.
- 한 번에 하나의 URL만 처리한다(여러 URL 일괄 변환 없음).

이 가정들은 검토 중 잘못됐다고 판단되면 바로 뒤집어도 되는 저비용 선택입니다.

## 제외 범위와 이유

- 로그인, 계정, 변환 이력 저장 — 요청 범위 밖이며 1회성 도구 성격과 맞지 않는다.
- 여러 URL 일괄 변환 — 요청 범위 밖.
- ChatGPT/Claude API를 직접 호출해 응답까지 받아오는 것 — 이 서비스는 핸드오프까지만
  담당하고, 실제 대화는 각 서비스 화면에서 이루어진다.

## 보류된 사항

- robots.txt나 이용약관상 크롤링이 제한된 사이트를 만났을 때의 별도 처리 정책은
  정하지 않았다. 지금은 "가져오기 실패"로 묶어 처리한다.

## 남은 리스크

- defuddle의 본문 추출 품질은 사이트 구조에 따라 달라질 수 있다(광고/내비게이션
  문구 혼입, 본문 일부 누락 등). 완벽한 추출을 보장하지 않는다.
- 로그인 필요 페이지, 페이월, 클라이언트 렌더링(SPA) 의존 페이지는 서버 fetch만으로
  본문을 가져오지 못할 수 있다 — 이 경우 "가져오기 실패" 경로로 처리된다.
